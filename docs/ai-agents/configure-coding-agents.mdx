Use Declarative Forms with your coding agent by giving it the documentation context first, then asking it to create or edit a `version: 1` YAML form.

## Give your agent the docs context

Mintlify exposes documentation in formats that agents can read directly:

| Route | Use it for |
| --- | --- |
| `/llms.txt` | A compact index of the documentation pages and their descriptions. |
| `/llms-full.txt` | The full documentation site as one Markdown file. Use this when the agent can load a URL or long context. |
| `/skill.md` | A generated capability summary for public Mintlify docs sites. Use this when an agent supports skills or capability files. |

Use these documentation URLs:

```text
https://docs.declarativeforms.com/llms.txt
https://docs.declarativeforms.com/llms-full.txt
https://docs.declarativeforms.com/skill.md
```

<Info>
For most coding agents, start with `/llms-full.txt`. If the agent needs a smaller entry point, give it `/llms.txt` first and ask it to open only the pages relevant to the form you want.
</Info>

## Use a clear prompt

Ask the agent for a complete YAML file, not a partial fragment, unless you are editing an existing form.

```text
Use the Declarative Forms documentation at https://docs.declarativeforms.com/llms-full.txt.

Create a complete Declarative Forms YAML file for:
<describe the form, audience, fields, routing, validation, and submission destination>

Requirements:
- Use version: 1.
- Use only documented field types, validators, connections, and completion settings.
- Keep field and section ids lowercase, stable, and snake_case.
- Include required validators where the user must answer.
- Use visible_when or conditional section navigation only when the behavior requires it.
- If something is ambiguous, make a conservative assumption and list it after the YAML.
```

## Review the generated YAML

Before committing an agent-generated form, check that:

- The file starts with `version: 1`.
- Every section has a stable `id`.
- Every field has a stable `id`, `type`, and `label`.
- `next` points to another section id or `done`.
- Conditional expressions reference fields through `data.<field_id>`.
- Connections use a documented `type`, such as `email` or `webhook`.

For a first form, compare the result with [Create a form](/getting-started/create-a-form). For field-specific options, use the [Field Types](/field-types) pages.
