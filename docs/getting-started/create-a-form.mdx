title: "Create a form"
description: "Commit a YAML form to GitHub and open its stable source URL."
---

Declarative Forms reads version 1 YAML from GitHub. GitHub stores and reviews
the definition; your deployment validates and renders it.

<Info>
This guide assumes you already have a deployment. See
[Self-host Declarative Forms](/getting-started/self-host).
</Info>

## Create the YAML file

Create `forms/contact.yaml` in a GitHub repository:

```yaml contact.yaml
version: 1
title: "Contact us"
description: "Send us a message and we will get back to you."

sections:
  - id: contact
    title: "Your details"
    fields:
      - id: full_name
        type: short_text
        label: "Full name"
        placeholder: "Jane Smith"
        validators:
          - required

      - id: email
        type: email
        label: "Email address"
        placeholder: "jane@example.com"
        validators:
          - required

      - id: message
        type: long_text
        label: "Message"
        validators:
          - required

    next: done
```

Commit and push the file. Unknown properties and unsupported field types are
rejected with their YAML path instead of being silently ignored.

## Open the stable URL

Use the GitHub owner, repository, and YAML path:

```text
https://forms.example.com/<owner>/<repository>/<path>
```

For `forms/contact.yaml` in `acme/company-forms`:

```text
https://forms.example.com/acme/company-forms/forms/contact
```

The `.yaml` suffix is optional. The URL stays source-addressed and does not
redirect to a database-generated form ID.

GitHub's default branch is used automatically. To pin another branch, tag, or
commit, add a `ref` query parameter:

```text
https://forms.example.com/acme/company-forms/forms/contact?ref=release-v1
```

## Public repositories

No GitHub credential is required. An arbitrary public repository is
render-and-store only: its `connections` and external measurements are not
trusted or executed by the deployment.

## Trusted and private repositories

The deployment operator allowlists trusted repositories in `.env`:

```dotenv
GITHUB_TRUSTED_REPOSITORIES=acme/company-forms,acme/internal-forms
```

For a private repository, also configure a fine-grained token with read-only
Contents access to that repository:

```dotenv
GITHUB_TOKEN=github_pat_replace_me
```

Restart the API container after changing deployment configuration:

```bash
docker compose --env-file .env --file docker/compose.yaml up -d --no-deps --force-recreate api
```

Trusted definitions may execute configured email and HTTPS webhook
connections. The GitHub token stays on the server. The form URL itself is a
share link: respondents do not authenticate with GitHub.

## Verify changes

1. Open the source URL and confirm the form loads.
2. Submit without a required answer and confirm a field error appears.
3. Complete the form and confirm its completion message appears.
4. Edit the YAML, commit, and wait up to 30 seconds for the in-memory source
   cache to expire.
5. For a trusted connection, inspect its delivery state through the protected
   submission API.

## Troubleshooting

- **Invalid form YAML:** use the reported line and column to fix YAML syntax.
- **Invalid form definition:** use the reported property path and compare it
  with the [YAML reference](/reference/yaml-schema).
- **GitHub source not found:** verify owner, repository, path, and `ref`; for a
  private repository, verify the allowlist and token permissions.
- **GitHub rate limit reached:** wait for the reported retry period or add an
  appropriately scoped token to an allowlisted repository.
- **Connection did not run:** only allowlisted repositories are trusted to
  execute connections.
